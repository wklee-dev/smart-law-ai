워드 사용가이드
이 배포본은 Python 소스 실행 패키지이며 Windows .exe 바이너리가 아닙니다. 운영 DB나 수집된 첨부파일은 압축파일에 포함하지 않습니다.
3. 설치와 실행방법
Windows 10/11에서 Python 3.10 이상을 먼저 설치합니다. 설치 시 ‘Add Python to PATH’를 선택하거나 Python Launcher(py)를 설치합니다. 관리자 권한은 필수가 아니며, DB/첨부 폴더에 대한 쓰기 권한과 HTTPS 인터넷 접속이 필요합니다. 운영 DB는 지침에서 지정한 D:\SQLiteDB\smart_law_ai.db를 사용합니다. 다른 위치로 옮기거나 경로를 임의로 변경하지 마세요.
ZIP 파일은 ‘모두 압축 풀기’로 일반 폴더에 해제합니다. ZIP 내부에서 BAT를 바로 실행하지 마세요. 경로가 지나치게 길지 않은 C:\Tools\customs_admin_notice_crawler 등의 폴더를 권장합니다.

3.1 페이지는 실행 파라미터로만 지정
V1.4는 실행 중 페이지를 묻지 않습니다. run.bat 뒤에 --pages 파라미터를 처음부터 전달합니다. 파라미터가 없으면 곧바로 전체 페이지 범위를 수집합니다. --pages에 빈 문자열을 전달해도 전체입니다. 구버전 config.json에 pages 값이 있어도 페이지 파라미터를 생략하면 전체를 수집하도록 해당 설정값은 사용하지 않습니다.

명령

Python 직접 실행도 동일합니다. py -3 crawler.py는 전체, py -3 crawler.py --pages 2는 2페이지입니다. --pages 없이 다른 파라미터만 전달해도 전체 범위입니다. 예를 들어 run.bat --verify-files는 전체 범위의 무결성을 확인하고 수집합니다.
페이지 번호는 작성일 내림차순, 페이지당 건수 기준입니다. 기존 기본값 page_size=100은 바꾸지 않았습니다. 따라서 기본 2페이지는 목록 101~200번째 게시글입니다. 포털의 10건 표시 화면에 맞추려면 --page-size 10을 쓰거나 config.json의 page_size를 10으로 설정합니다. 10건 기준 2페이지는 11~20번째입니다.
잘못된 형식, 0/음수/역방향 범위, 존재하지 않는 페이지는 오류로 중단합니다. 잘못된 파라미터를 전체로 임의 전환하지 않습니다. 선택 범위 밖 상세/첨부는 다운로드하지 않으며, 범위 확인용 1페이지의 목록 요청만 수행할 수 있습니다.
선택 페이지 성공은 종료코드 0이며 실행 이력에 selected/selected_full과 pages/page_size를 기록합니다. 선택 페이지 실행을 ‘초기 전체 수집 완료’로 기록하지 않습니다. 다음 전체 실행에서는 이미 성공한 자료를 재사용하면서 나머지를 수집합니다. 페이지 번호는 새 글 추가에 따라 이동하므로 정기적인 전체 범위 증분 확인을 권장합니다.
3.2 시작·진행 표시
run.bat는 Python 탐지 전에 영문 시작 안내를 표시합니다. Python 찾기/필수 라이브러리 확인/크롤러 시작 단계와 실제 Python 경로를 표시합니다. 크롤러는 DB 준비, 부서 코드 조회, 목록 요청, 상세/첨부 진행을 표시하며 출력 지연을 줄이기 위해 비버퍼 출력(-u)을 사용합니다. 모든 BAT 파일에서 pause를 제거했습니다. 정상 완료와 오류 모두 키 입력 대기 없이 종료코드를 반환합니다. 더블클릭으로 실행하면 종료 후 창이 닫힐 수 있으므로 진행과 결과를 계속 보려면 이미 열린 명령 프롬프트에서 실행하세요. 로그 파일은 기존처럼 logs에 남습니다.
V1.4는 실행 전 DB 백업을 하지 않습니다. 지침에 없는 백업 함수·호출·설정을 제거했으며, 구버전 config.json에 backup_before_run=true가 남아 있어도 해당 키를 무시합니다. 백업 폴더나 DB 복제 파일을 생성하지 않습니다. 기존 버전에서 만들어진 파일을 자동 삭제하거나 기존 DB/첨부 위치를 변경하지도 않습니다.
3.3 가상환경 없는 설치 방식
V1.4도 가상환경 폴더를 만들거나 활성화하지 않습니다. 설치된 일반 Python을 직접 사용하며 setup.bat는 선택된 Python의 pip에 --user 옵션을 적용해 현재 Windows 사용자 영역에 라이브러리만 설치합니다. 라이브러리 설치는 최초 한 번 필요하며 Python 3.10 이상은 PC에 설치되어 있어야 합니다. .exe 방식이나 무설치 Python 내장 방식은 아닙니다.
직접 명령으로 설치하려면 py -3 -m pip install --user -r requirements.txt를 실행하고, py -3 crawler.py로 시작합니다. py가 없는 PC에서는 모든 명령의 py -3를 python으로 바꾸세요. 배치파일은 이 선택을 자동으로 처리합니다. Python이 여러 개 설치되어 있다면 설치와 실행에 같은 실행기를 사용해야 합니다.
--user 설치 라이브러리는 같은 사용자의 해당 Python에서 사용하는 다른 프로그램과 공유될 수 있습니다. 별도 환경 격리는 하지 않습니다. 조직 정책으로 사용자 라이브러리가 차단되었거나 사용자 사이트가 비활성화된 경우, 일반 Python의 설치 정책을 확인해야 합니다. 이미 활성화한 Python 가상환경 안의 실행기만 발견되는 경우에는 일반 명령 프롬프트에서 재실행하도록 안내하고 중단합니다.
기존 V1.0을 사용했다면 기존 DB/첨부폴더/config.json 경로를 그대로 사용할 수 있습니다. 테이블 정의와 schema_version=1.0은 유지하므로 자료를 다시 만들 필요가 없습니다. V1.4 폴더에서 setup.bat와 run.bat를 실행하면 됩니다. 기존 가상환경 폴더를 자동으로 삭제하거나 변경하지 않습니다.

5. 전량·증분 수집과 첨부 저장 규칙
페이지를 지정하지 않은 최초 실행에서는 검색 조건을 비운 목록 API의 모든 페이지를 수집합니다. 페이지 지정 시에는 선택한 페이지의 건수만 검증합니다. 사이트가 반환한 총 건수와 고유 게시글 ID 수를 비교해 목록 누락을 검증한 뒤 상세 수집을 시작합니다. 진행 중 전체 건수가 바뀌거나 페이지에 중복 ID가 나타나면 성공 처리하지 않고 재실행을 안내합니다.
후속 전체 범위 실행에서는 목록 전체를 확인합니다. 페이지 지정 시에는 선택한 범위의 목록만 대조합니다. 고유 게시글 ID가 신규이거나, 제목/작성일/부서/공고 정보 등 목록 메타데이터의 해시가 바뀌거나, 이전 상세 수집이 실패한 경우에만 상세를 다시 가져옵니다. 갱신은 동일 ID에 대한 UPDATE이며 중복 행을 만들지 않습니다. 최초 수집 중 중단된 뒤 재실행하면 이미 성공한 상세는 재사용하고 미처리 항목부터 이어받습니다.
기존 게시글의 본문만 바뀌고 목록 정보는 그대로인 경우 기본 증분 실행만으로는 감지하지 못합니다. 이러한 변경까지 확인할 때는 run_full.bat 또는 --full을 실행하세요. 같은 file_id의 서버 파일 바이트가 교체되었는지는 기본 실행이나 --full에서 원격 재다운로드로 확인하지 않습니다. --verify-files는 로컬 저장 파일의 무결성을 확인하는 기능입니다.

7. 저장 결과 확인 SQL
DB Browser for SQLite 등에서 아래 쿼리를 사용할 수 있습니다. 단순 조회만 수행하며 기존 데이터를 수정하지 않습니다.
최신 게시글:
SELECT notice_id, title, department_name, written_date, detail_status
FROM clip_admin_notices
ORDER BY written_date DESC, notice_id DESC
LIMIT 20;
현재 첨부파일:
SELECT n.title, a.original_name, a.local_path, a.download_status,
       a.file_size, a.sha256
FROM clip_admin_notices n
JOIN clip_admin_attachments a ON n.notice_id = a.notice_id
WHERE a.is_current = 1
ORDER BY n.written_date DESC;
전체 저장 현황:
SELECT detail_status, COUNT(*) AS cnt
FROM clip_admin_notices GROUP BY detail_status;
SELECT download_status, COUNT(*) AS cnt
FROM clip_admin_attachments WHERE is_current = 1
GROUP BY download_status;
SELECT * FROM clip_admin_crawl_runs ORDER BY run_id DESC LIMIT 10;
SELECT * FROM clip_admin_crawl_errors ORDER BY error_id DESC LIMIT 30;

9. 검증 결과 및 확인 범위
2026-10-15 Sandbox에서 Python 문법 검사와 V1.4 오프라인 자동 테스트 81개가 모두 통과했습니다. 테스트는 기존 테이블 보존, 스키마 충돌 중단, 날짜/폐지제정 비필터링, 신규/동일 날짜/소급 등록, 중복 방지, 변경 갱신, 첨부 실패/누락/해시 복구, 표본 제한, 실제 상세 HTML 등을 확인했습니다.
V1.0에서 수행한 실사이트 목록 854건·상세 3건·첨부 10개 확인 결과는 그대로 참조합니다. 이번 V1.4에서는 자동 백업 구현 제거, 구버전 백업 설정의 미적용, 기존 데이터 보존, 백업 파일/폴더 미생성 및 기존 실행 규칙 유지를 확인했습니다. 기존 DB 연결의 backup 메서드가 호출되면 실패하도록 구성한 테스트에서도 정상 완료했습니다. 실사이트 수집은 다시 수행하지 않았으며 V1.2의 2페이지 표본(선택 목록 10건, 상세 1건, 첨부 3개) 확인 결과를 참조합니다. 상세 확인 범위는 배포본의 검증결과.md에 기록합니다. 운영 DB D:\SQLiteDB\smart_law_ai.db는 이 환경에 제공되지 않아 직접 실행하지 않았습니다. Windows BAT 실행은 이 Linux 환경에서 직접 검증하지 못했으며, Windows용 py/python 탐지·일반 Python 직접 실행·오류코드 전달 로직을 포함했습니다.
전체 목록 검증과 상세/첨부 표본 검증을 구분하며, 실제 전체 게시글·첨부 전량 다운로드가 완료된 데이터셋을 배포하는 것은 아닙니다. 사용자의 PC에서 run.bat를 파라미터 없이 실행하면 입력 대기 없이 전체 범위를 수집합니다. 기존 성공 자료는 증분 규칙에 따라 재사용합니다.
