1. 목적·범위 및 배포 구성
항목
사실 및 운영 의미
데이터 원천
공개 PSR 화면 https://www.ftapass.or.kr/psr/view.do 의 화면 스크립트가 사용하는 POST https://www.ftapass.or.kr/psr/getAll.json.
원문성
각 조회의 파싱된 JSON 필드를 빠짐없이 canonical JSON으로 재직렬화하고 해시 이름으로 보존한다(HTTP 응답 byte 단위 원문 보존은 아님). 생성 XLSX는 이 JSON을 변환한 자체 산출물이며, 확인되지 않은 공식 Excel 다운로드 파일이 아니다.
HS 개정판
기준년도는 달력 2026년이 아니라 HS 개정판이다. 실행 시 화면 옵션을 동적으로 발견하며, 사전 확인 값은 HS2022·HS2017·HS2012·HS2007·HS2002이다.
입력 해석
원본 「관세청_HS부호_2026_6단위.xlsx」는 12,470행이나, 비어 있지 않은 HS 데이터는 5,613개 고유 HS6이다. 배포 input/hs_codes.xlsx는 헤더 포함 5,614행(데이터 5,613개)으로 정리되어 있다. A열 수식은 지원하지 않아 즉시 검증 오류가 나므로, 수식 결과는 값으로 붙여넣어야 한다.
포함/비보장
협정코드를 비우고 useYn을 필터하지 않아 서버가 반환하는 모든 협정을 요청한다. 서버가 반환하지 않는 역사·폐지 데이터의 완전성은 보장하지 않는다. 2026 코드집이 과거 HS 개정판에서 사라진 코드를 복구·변환하지도 않는다.
처리 방식
요청은 순차 실행이다. 기본 최소 간격 1초, timeout 45초, retries 4회(최초 요청 외 추가 재시도), page-size 100, max-consecutive-failures 5이다. 429/5xx와 연결·시간초과는 지수 backoff, 401/403/비JSON은 즉시 중단하며, 연속 HS 조회 오류 5회도 대량 실패 방지를 위해 중단한다. TLS 인증서는 기본 검증한다.
2. 실행 전 확인
확인 항목
확인 방법 / 합격 기준
환경
Windows 10/11, Python 3.10 이상, 인터넷 연결 및 D: 드라이브 쓰기 권한을 준비한다.
배포물
패키지 루트에 fta_pass_crawler.py, requirements.txt, input\hs_codes.xlsx, setup.bat, plan.bat, smoke_test.bat, run_all.bat, run_collect.bat, run_import.bat, run_export.bat가 있어야 한다. BAT 메시지는 ASCII 영어이며 CRLF 형식이다.
입력
기본 input\hs_codes.xlsx의 첫 시트/첫 열을 사용한다. 헤더 후보를 인식하고 6·10자리 숫자만 허용하며 10자리는 앞 6자리로 사용한다. 숫자 셀에서 사라진 앞 0은 6/10자리로 보정한다. 잘못된 셀이 있으면 수집 전 중단한다.
DB 안전
기존 D:\SQLiteDB\smart_law_ai.db가 있으면 최초 FTA-PASS 도입 전에 backups\&lt;DB명&gt;_before_fta_pass_&lt;시각&gt;.db를 만든다. 기존 데이터 테이블은 변경하지 않는다.
충돌 안전
이미 fta_pass_% 테이블이 있으나 schema_version을 읽을 수 없거나 버전이 1이 아니면 변경을 거부하고 중단한다. 삭제·DROP·마이그레이션은 수행하지 않는다.
회귀 검증
오프라인 unittest 19개가 통과했다. 다만 실제 공개 사이트는 변경될 수 있으므로 운영 전 smoke_test를 별도로 수행한다.
3. 표준 실행 절차 (반드시 smoke 성공 후 전체 실행)
순서
실행 위치 / 명령
수행 내용·판정
1
패키지 폴더에서 setup.bat 더블클릭
최초 1회. Python 3.10+를 점검하고 .venv를 만든 뒤 requirements.txt를 설치한다. “Setup complete” 후 다음 단계로 간다.
2
plan.bat
입력과 --years 옵션을 검증하고 공개 화면에서 HS 개정판 옵션을 발견한다. DB는 열지 않지만 downloads 하위 FTA-PASS_원산지결정기준\metadata 및 logs\crawler.log는 저장한다. 기본 5,613 × 발견 개정판 5 = 28,065 기본 쿼리이며 페이지·재시도 요청은 추가된다.
3
smoke_test.bat
--limit 1로 단일 HS6만 all 단계로 수행한다. 운영 DB가 아닌 D:\SQLiteDB\fta_pass_smoke_test.db, D:\SQLiteDB\downloads\smoke_test 하위를 사용한다. exit 0 및 로그/보고서/원문/XLSX를 확인한 뒤에만 전체 실행한다.
4
run_all.bat
collect → import → export를 연속 수행한다. 중단·부분 실패는 같은 명령으로 재실행하여 성공·검증완료 원문을 건너뛰고 이어서 처리한다.
5
필요 시 분리 BAT
run_collect.bat, run_import.bat, run_export.bat로 단계를 분리한다. collect는 JSON 수집만, import는 원문 JSON 검증·DB 반영만, export는 현재 성공 스냅샷의 XLSX 생성만 수행한다.
BAT는 마지막에 exit code를 표시하고 창을 유지합니다. setup은 최초 1회, 이후에는 smoke_test 성공 확인 후 run_all을 권장합니다.

4. CLI 옵션 및 직접 실행
용도
명령 또는 옵션
정확한 동작
기본 전체
.venv\Scripts\python.exe fta_pass_crawler.py --input "input\hs_codes.xlsx" --years all --stage all
동적으로 발견한 모든 HS 개정판과 입력 HS6에 대해 수집·반영·내보내기를 수행한다.
단계 분리
--stage collect  |  --stage import  |  --stage export
collect=수집만, import=JSON 원문을 DB로 반영, export=DB 현재 성공 스냅샷을 XLSX로 생성. all은 세 단계를 순서대로 수행한다.
개정판 제한
--years HS2022,HS2017
collect/all에서는 화면에서 발견된 옵션만 허용한다. import/export에서는 HSnnnn 형식만 검증한다.
소규모 시험
--limit 3 --delay 2
입력의 고유 HS6 앞 3개만 실행하며 요청 최소 간격을 2초로 높인다. --limit은 양수여야 한다.
원문 재반영
--stage import --raw-dir import
지정 폴더 아래의 .json 번들을 재귀 탐색해 검증·반영한다. --raw-dir가 없으면 기본 raw 하위를 사용한다.
과거 원문 재수집
--force
이미 success인 작업도 다시 수집한다. 기존 raw/ 원문 및 DB 관측 이력은 보존하며, 오래된 번들이 더 최신 스냅샷을 덮어쓰지 않도록 비교한다.
통신 조정
--delay 1 --timeout 45 --retries 4 --page-size 100
기본값. retries는 첫 시도 이후 추가 재시도 횟수이며 page-size는 1~1000 범위다.
대량 실패 차단
--max-consecutive-failures 5
기본값은 연속 HS 조회 오류 5회다. 이 한도에 도달하면 대량 실패를 방지하기 위해 중단한다. 401/403/비JSON은 이 한도와 무관하게 즉시 중단한다.
계획만
--plan
입력 검증과 개정판 발견만 수행한다. DB를 열지 않는다.

6. Excel 내보내기 안전 규칙
규칙
처리 방식
HS6 선행 0
XLSX의 모든 문자열은 텍스트 형식으로 작성하므로 010121 등 선행 0을 보존한다.
수식 실행 방지
문자열 셀을 명시적으로 문자열 데이터 형식으로 기록해 수식으로 실행되지 않게 한다.
HTML/줄바꿈
origin_rule_html에는 서버 원문을, origin_rule_text에는 HTML &lt;br&gt;를 줄바꿈으로 바꾼 정리본을 병행 저장한다.
긴 셀
Excel 셀 한계 32,767자를 넘는 문자열만 XLSX에서 잘린다. DB raw_row_json·response_json 및 canonical 재직렬화 JSON 번들은 완전 보존된다.
행 한계
데이터 행이 1,048,575개에 도달하면 다음 시트로 분할한다. 각 시트는 헤더·필터·틀 고정을 갖는다.
7. SQLite 데이터베이스 설계 (소스 SCHEMA 인메모리 검증)
아래 컬럼은 배포 fta_pass_crawler.py의 SCHEMA 문자열을 SQLite :memory:에서 실행한 뒤 PRAGMA table_info / foreign_key_list / index_list로 인트로스펙션하여 작성하였다. FTA-PASS 전용 테이블은 모두 fta_pass_ 접두어를 사용하므로 기존 smart_law_ai.db의 업무 테이블과 논리적으로 분리된다.

운영 상태 전이·보존 원칙
대상
상태 / 검증
운영 의미
실행(crawl_runs)
running → completed 또는 partial_failed; 예외 시 failed; Ctrl+C 시 interrupted
실행 전체의 결과와 구성, 오류를 reports/&lt;run_id&gt;.json 및 DB에 남긴다.
작업(crawl_jobs)
pending → running → success 또는 failed; 종료 시 남은 running은 interrupted
작업마다 시도 횟수·예상/수신 행 수·오류·현재 원문 해시를 기록한다.
재시작 건너뜀
success + artifact_path 읽기 + SHA-256 일치 + bundle 구조/페이지/행 수 검증
모두 통과한 경우에만 재수집을 건너뛴다. 하나라도 불일치하면 다시 수집/반영 대상이다.
강제 재수집
--force
과거 raw 번들과 규칙/출처 이력은 보존한다. 오래된 archived bundle은 최신 job snapshot을 덮어쓰지 않는다.
원문/DB 반영
import 단계에서 페이지 요청·응답, 행 원문 JSON, 내용 해시, 원문 행 위치를 함께 기록
응답 byte 자체가 아니라 파싱된 모든 필드를 canonical JSON으로 재직렬화해 내용 보존·추적성을 제공한다.
운영 장애 대응표
징후
프로그램 동작
사용자 조치
401 / 403
SiteBlocked 예외로 즉시 중단한다. 다른 HS6에 대해 계속 반복 요청하지 않는다.
사이트를 수동 확인하고 접근 제한·로그인·정책 변화를 해소한 뒤 동일 명령으로 재시작한다.
비JSON 또는 응답 형식 변경
예상 JSON·jqGrid 키가 아니면 즉시 중단한다.
metadata/psr_view.html, crawler.log와 사이트 화면을 비교하고 소스 호환성을 점검한다.
429 / 5xx
Retry-After가 있으면 최대 300초, 없으면 최대 60초 지수 backoff로 재시도한다.
요청 간격을 높이고 서버 부하 시간대를 피한다. 반복 실패한 항목은 보고서에서 확인한다.
연결 오류 / timeout
기본 retries=4로 재시도한 후 해당 작업을 failed로 기록하고 다음 작업을 계속한다.
네트워크를 점검하고 동일 명령을 재실행한다. 필요한 경우 --timeout·--delay를 조정한다.
연속 조회 오류 5회
기본 --max-consecutive-failures 5에 도달하면 대량 실패를 피하기 위해 실행을 중단한다.
오류 원인을 해소한 뒤 재시작한다. 한도를 무리하게 늘리기 전에 사이트·입력·통신 상태를 확인한다.
번들 SHA / 구조 불일치
success 상태라도 resume skip하지 않고 다시 수집 또는 반영 대상으로 처리한다.
raw 파일을 임의 수정하지 말고 reports 및 artifact_path를 점검한다.
입력 검증 오류
잘못된 HS·빈 유효 코드·A열 수식은 수집 전에 중단한다.
A열을 6/10자리 값으로 정리하고 수식은 값으로 붙여넣은 뒤 다시 plan.bat부터 수행한다.
운영 원칙: 오류가 난 부분만 상태·오류 메시지와 함께 남기며, 기존 원문·DB 이력이나 기존 업무 테이블을 삭제하지 않는다. completed/partial_failed/failed 여부는 반드시 reports와 DB에서 함께 확인한다.
부록 A. 운영 조회 SQL 예시
아래 SQL은 SQLite CLI·DB Browser for SQLite 등에서 실행할 수 있다. 모두 읽기 전용 SELECT 예시이며 데이터를 수정하거나 삭제하지 않는다.
A-1. 최근 성공 스냅샷 조인
SELECT j.hs_version, j.query_hs6, r.agreement_name,
       r.origin_rule_text, s.observed_at, j.artifact_sha256
FROM fta_pass_rule_sources AS s
JOIN fta_pass_crawl_jobs AS j
  ON j.job_key = s.job_key AND j.artifact_sha256 = s.artifact_sha256
JOIN fta_pass_origin_rules AS r ON r.rule_hash = s.rule_hash
WHERE j.status = 'success'
  AND j.imported_sha256 = j.artifact_sha256
ORDER BY j.hs_version DESC, j.query_hs6, r.agreement_name, s.page_no, s.row_no
LIMIT 100;
A-2. 실패 작업
SELECT hs_version, query_hs6, status, attempts, updated_at, error_message
FROM fta_pass_crawl_jobs
WHERE status IN ('failed', 'interrupted')
ORDER BY updated_at DESC;
A-3. HS 개정판별 현재 성공 건수
SELECT hs_version,
       COUNT(*) AS successful_queries,
       SUM(COALESCE(received_records, 0)) AS received_records
FROM fta_pass_crawl_jobs
WHERE status = 'success' AND imported_sha256 = artifact_sha256
GROUP BY hs_version
ORDER BY hs_version DESC;
