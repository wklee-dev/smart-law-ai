# 관세법령정보포털 조약·협정 크롤러

## 개요

이 프로그램은 관세법령정보포털(CLIP)의 **조약/협정** 목록을 API로 페이지 단위 조회하고, 각 조약의 상세 본문 및 첨부파일을 내려받아 기존 SQLite 데이터베이스에 추가 저장합니다. 대상 화면은 CLIP의 조약/협정 전체 목록입니다.[1]

기존 `clip_admin_rule.db` 파일을 삭제하거나 기존 테이블을 수정하지 않습니다. 대신 `clip_` 접두사의 새 테이블만 생성합니다. 수집이 중단되어도 이미 처리된 조약과 파일은 보존되며, 같은 명령을 다시 실행하면 조약 레코드는 최신 데이터로 갱신되고 성공한 첨부파일은 기본적으로 다시 받지 않습니다.

> **보관 경로 원칙:** 첨부파일은 데이터베이스가 있는 폴더 아래 `attachments\조약협정\<조약일련번호>`에 저장합니다. 화면별 파일을 분리하여 이후 다른 크롤링 화면을 추가하더라도 파일 출처를 유지합니다.

## 사전 준비

| 항목 | 요구 사항 |
| --- | --- |
| 운영체제 | Windows 10/11 권장 |
| Python | 3.10 이상 |
| 네트워크 | 관세법령정보포털 접속 가능 환경 |
| 데이터베이스 | `D:\SQLiteDB\clip_admin_rule.db` 또는 지정 경로의 SQLite DB |

프로젝트 폴더에서 다음 명령을 한 번 실행합니다. Windows PowerShell 기준입니다.

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Windows에서 PowerShell 실행 정책 때문에 가상환경 활성화가 차단되면 `Set-ExecutionPolicy -Scope Process Bypass`를 실행한 뒤 다시 활성화합니다. 가상환경을 사용하지 않는 경우에도 `pip install -r requirements.txt` 후 명령을 실행할 수 있습니다.

## 실행 방법

기본 데이터베이스 경로는 설계서에 지정된 `D:\SQLiteDB\clip_admin_rule.db`입니다. 기본 명령은 모든 페이지를 페이지당 10건씩 처리합니다. 포털에 새 조약이 추가되면 마지막 페이지 수는 자동으로 다시 계산됩니다.

```powershell
py clip_treaty_crawler.py
```

첨부파일을 포함한 수집은 포털 서버에 부담을 주지 않도록 기본적으로 요청 사이에 0.35초를 대기합니다. 운영 환경에서는 이 값을 낮추지 않는 것이 좋습니다.

| 목적 | 예시 명령 | 동작 |
| --- | --- | --- |
| **1페이지 시험 수집** | `py clip_treaty_crawler.py --page 1` | 첫 목록 페이지의 조약, 본문, 첨부파일만 수집합니다. |
| **향후 페이지 단위 수집** | `py clip_treaty_crawler.py --page 4` | 목록의 4페이지 한 페이지만 수집합니다. |
| **페이지 구간 수집** | `py clip_treaty_crawler.py --start-page 3 --end-page 6` | 3~6페이지를 포함하여 수집합니다. |
| **전체 수집** | `py clip_treaty_crawler.py --start-page 1` | 1페이지부터 포털의 마지막 페이지까지 수집합니다. |
| **50건 단위 전체 수집** | `py clip_treaty_crawler.py --page-size 50` | 포털 목록을 페이지당 50건으로 요청합니다. |
| **본문·목록만 확인** | `py clip_treaty_crawler.py --page 1 --no-attachments` | 첨부파일 다운로드 없이 메타데이터만 SQLite에 기록합니다. |
| **특정 국가 검색** | `py clip_treaty_crawler.py --country 아랍에미리트` | 포털의 체결국가명 검색 조건을 적용합니다. |
| **특정 조약명 검색** | `py clip_treaty_crawler.py --treaty-name 자유무역협정` | 포털의 조약명 검색 조건을 적용합니다. |
| **기존 첨부파일도 다시 수집** | `py clip_treaty_crawler.py --page 1 --refresh-attachments` | 이미 성공한 첨부파일도 재다운로드합니다. |
| **다른 DB에 시험 저장** | `py clip_treaty_crawler.py --db .\data\clip_admin_rule_test.db --page 1` | 운영 DB를 건드리지 않고 별도 DB에 저장합니다. |

`--page`는 정확히 한 페이지를 선택하는 옵션입니다. 이후 작업에서 특정 페이지를 추가로 가져오려면 단순히 페이지 번호만 바꾸면 됩니다. 예를 들어 1~5페이지를 이미 수집한 뒤 6페이지만 추가하려면 `--page 6`을 실행합니다.

명령 프롬프트에서 페이지 번호만 입력하는 방식을 선호하면 `run_page.bat`를 더블클릭할 수 있습니다. 이 보조 실행 파일은 페이지 번호를 질문한 뒤 동일한 기본 DB 경로로 한 페이지를 수집합니다.

## 저장 구조

SQLite 데이터베이스에는 다음 테이블이 추가됩니다.

| 테이블 | 용도 | 주요 식별자 |
| --- | --- | --- |
| `clip_treaties` | 조약 기본 정보, 목록 API 원문, 상세 HTML, 상세 텍스트, 국문·영문 본문 | `trty_srno` |
| `clip_treaty_attachments` | 첨부파일명, 첨부파일 ID, 로컬 상대 경로, 파일 크기, SHA-256, 다운로드 상태·오류 | `attachment_id` |
| `clip_treaty_crawl_runs` | 실행 시각, 요청 범위, 성공·실패 건수, 오류 메시지 | `run_id` |

첨부파일의 DB 상태는 `downloaded`, `pending`, `failed` 중 하나로 기록됩니다. `failed`가 있더라도 조약 본문과 나머지 파일 수집은 계속 진행됩니다. 실행 종료 코드가 `2`이면 첨부파일 일부만 실패한 상태이므로 `clip_treaty_attachments.last_error`를 확인한 뒤 동일 페이지를 재실행하면 됩니다.

## 데이터 확인 예시

SQLite 도구에서 다음 조회로 최근 수집된 조약 및 파일 상태를 확인할 수 있습니다.

```sql
SELECT trty_srno, treaty_name, category_name, effective_date, crawled_at
FROM clip_treaties
ORDER BY effective_date DESC;

SELECT t.treaty_name, a.file_name, a.download_status, a.relative_path, a.last_error
FROM clip_treaty_attachments AS a
JOIN clip_treaties AS t ON t.trty_srno = a.trty_srno
ORDER BY t.effective_date DESC, a.file_name;
```

## 검증

프로그램 배포 전에는 다음 명령으로 문법 검사와 단위 테스트를 실행할 수 있습니다.

```powershell
py -m compileall -q clip_treaty_crawler.py tests
py -m unittest discover -s tests -v
```

테스트는 페이지 선택 인자, Windows 파일명 정규화, 중복 노출된 첨부파일의 제거, SQLite 스키마 및 저장 동작을 검증합니다. 실제 포털에 요청하지 않으므로 안전하게 반복 실행할 수 있습니다.

## 운영 유의사항

이 도구는 공개된 포털의 문서 보존을 목적으로 합니다. 포털의 이용 조건, 저작권 고지, 시스템 부하 정책을 준수해야 합니다. 대량 수집 시에는 기본 대기 시간을 유지하고, 업무 시간대에는 `--page` 또는 작은 페이지 구간으로 나누어 실행하는 방식을 권장합니다. 포털의 UI나 API 형식이 변경되면 목록 또는 첨부파일 요청 부분을 조정해야 할 수 있습니다.
