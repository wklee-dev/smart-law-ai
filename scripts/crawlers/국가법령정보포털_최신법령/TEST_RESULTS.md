# V1.0 검색 오류 수정본 — 시험 결과

검증일: 2026-10-19(KST). 환경: Linux 샌드박스, Python 3.12. 사용자 Windows나 `D:\SQLiteDB\smart_law_ai.db`에 직접 접근하지 않았으며, 모든 실접속 시험에는 별도 시험 DB를 사용했습니다.

## 확인된 실패와 수정

사용자가 첨부한 `crawler_2026-10-17.log`에는 7개 수집대상에서 총 658번 조회했으나 검색·선별·본문·파일이 모두 0건인 실행이 `completed`로 기록되어 있었습니다. Python 설정 읽기·엑셀 로드·DB 초기화 단계는 통과한 실행입니다.

로그의 첫 검색어 묶음을 공식 목록 요청으로 재현했습니다. 시행법령에서 `"관세법"`은 11건, `"관세법" + "관세법 시행령"`도 11건이었습니다. 반면 동일 묶음의 검색어 3개·4개·5개를 큰따옴표와 `+`로 연결한 요청은 HTTP 200이어도 0건이었습니다. 서로 다른 짧은 법령명 5개로도 0건이 재현되었습니다. 단일·2개 검색 성공만으로 기존 최대 5개 묶음의 정확성을 검증한 것은 불충분했습니다.

수정본은 **K열 값을 하나씩 검색하고 결과를 합집합으로 병합(OR)**합니다. 서버 다중 OR 표현을 사용하지 않으며, 그 표현을 다시 요청하면 입력 검증에서 거부합니다. 공백·가운뎃점 정규화 중복은 제거하지만 관련 gubun과 일치 K값은 모두 연결합니다. 같은 대상·같은 버전의 상세·파일은 한 번 수집합니다.

오류 없이 실행되었더라도 전체 선별 결과가 0건이면 `completed`가 아닌 **`no_results`·종료코드 2**와 명확한 경고를 기록합니다. 실제 검색 결과가 없는 대상이나 날짜 조건 때문에 0건인 경우도 이 상태로 표시하며, 0건이라는 사실만으로 네트워크 오류를 단정하지 않습니다. 기존 자료는 삭제하지 않습니다.

- 논리 검색 469개, 첫 페이지 요청 469회, 실패 검색 0개.
- 검색 결과 행 누계 365개, 중복 병합 후 DB 목록 242건.
- DB 실행 이력은 `completed`, 종료코드 0.
- 목록 전용이므로 본문·부칙·별표·파일을 요청하지 않았습니다.

## 일곱 대상과 OR 합집합 실접속 검증

K열 gubun 1(관세법), 248(음악산업진흥에 관한 법률 시행규칙)을 각각 단일 검색하여 합쳤습니다. 각 검색어의 첫 페이지를 확인한 중복 병합 목록은 공포법령 63건, 시행법령 12건, 시행예정법령 6건, 폐지법령 50건이었습니다. 한시법령·한시조문·위헌조문에서는 이 두 검색어에 대한 결과가 0건이었습니다.

시행법령 합집합에 서로 다른 두 K값의 gubun 1·248 결과가 모두 포함되는 것을 확인했습니다. 이는 두 K값을 동시에 만족해야 하는 AND 수집이 아닙니다. 본문 1건과 PDF 1개도 시험하여 PDF 시그니처·SHA-256 및 재실행 파일 재사용을 확인했습니다. 이 시험은 각 검색어 첫 페이지만 조회했으며, 공포법령의 28페이지·폐지법령의 4페이지 전부를 실측하지 않았습니다.

결과: `live_k_column_or_result.json`. 재현 명령: `python tests/live_smoke.py --run`(임시 DB만 사용).

## 유지된 조건과 한계

1번 메뉴는 목록만 저장하고 CSV나 다운로드를 만들지 않습니다. 2번 메뉴는 대상별 키워드 검색·목록 저장 후 상세와 제공 파일을 수집합니다. 3번·4번 메뉴, 대상별 BAT, 기본 DB 경로 및 `llc_v1_` 스키마는 유지했습니다. 첨부파일은 기본 다운로드 경로 아래 수집대상 하위 폴더에 저장합니다. 가상환경·DB 백업·CSV 내보내기 기능은 없습니다.

수집 화면은 최신법령 7개입니다. 행정규칙 전용 화면은 이번 프로그램에 없습니다. Windows Python 실행기·D드라이브 권한·사용자 DB의 실제 상태는 해당 PC에서 확인해야 합니다. 엑셀 셀 전체 K값을 검색하는 기존 기준을 유지하므로, 그 값과 다른 공식 법령명은 임의로 추측하거나 치환하지 않습니다.
